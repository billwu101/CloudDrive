# 助理驗收測試方案（完整版，2026-07-22）

> 依 2026-07-21/22 真模型驗收跑批的實測經驗收斂。目標：把「件件分開測」升級為
> 「可信、可重複、涵蓋完整生命週期」的驗收方案。原始數據見 `backend/eval/out/acceptance-*`（gitignored）。

## 0. 一句話現況

本地 gemma4:26b 助理：**唯讀工作流、技能生成(+執行)、簡單特徵 93–100%；複雜多步規劃（M5）是真弱點（~10–30%）**。
過夜第一版的難看數字（M3 5%/M5 0%）主因是**評分模式套錯**（真模型誤用 mock 的 strict 精確比對）——已修（`--no-strict-steps`）。

## 1. 測試分層（每層測什麼、測不到什麼）

| 層 | mode | 測到 | 測不到 | 對應需求 |
|---|---|---|---|---|
| L1 規劃正確性 | `api --llm real --no-strict-steps` | 對話→規劃步驟/確認閘/記憶指涉/技能提案 | 工具真執行、生成碼能跑 | FR-18/19、記憶、FR-20(生成) |
| L2 預寫技能執行 | `exec` | 沙箱跑**預寫**技能、驗產出 | 模型生成的碼 | FR-21(執行) |
| L3 生成技能執行 | `gen_exec_probe`（新） | 模型**生成**碼→沙箱→驗產出 | UI/右鍵流程 | FR-20→21（半鏈） |
| L4 UI 全鏈 | `browser` | 登入→面板→生成→核可→右鍵執行→驗產出 | — | FR-21 + 完整生命週期（半鏈） |
| **L5 整合生命週期〔缺〕** | 待建 | 一個情境串起**規劃+確認+發現缺技能+生成+執行+寫回** | — | 情境三（目前只有手動 E2E ⬜） |

**關鍵洞察**：L1–L4 各測一段;**沒有任一自動案例把「多步規劃+確認」與「生成+執行」串成同一情境**——這是最大的完整性缺口（見 §4）。

## 2. 方法學鐵律（這批實測血淚換來的）

1. **真模型一律 non-strict 評分**（`--no-strict-steps`）。strict 精確比對是給 mock/寫死計畫用的；真模型計畫非確定性，strict 連 DB 狀態一變就飄（M2 strict 空庫90%→種子50%，non-strict 兩者都100%）。
2. **每案至少 runs=5**：機率性系統要 pass-rate/變異，不看單次。
3. **測試庫要有種子資料**：空庫會讓「操作既有檔」的案例在規劃層就反問澄清（不影響評分，但影響 L2/L4 真執行與 M3/M5 有目標的規劃）。標準種子：≥3 資料夾 + ≥12 文本檔（名稱含 report/invoice/photo… 供 search）。
4. **生成技能要真執行驗產出**（L3/L4），不能只驗「有沒有生成」——靜態通過 ≠ 能用（曾見 py7zr API 幻覺，靜態過、執行才露）。
5. **每批結果附 `meta.json`**：模型、DB(種子與否)、`LLM_*_DISABLE_THINKING`、評分模式、runs、日期、對照組。設定不記，數字無法比較。
6. **judge 可選**：純確定性斷言已涵蓋主體;rubric 類才需 judge。

## 4. 建議補的關鍵測試：L5 整合生命週期

寫一個（或數個）**單一情境**案例，串起完整鏈，例如：
> 「幫我把根目錄的 `.log` 檔壓成一個封存並放到『封存』資料夾」——助理需：①規劃（list→篩選）②發現沒有「壓縮」技能 ③**生成**壓縮技能 ④**確認/核可** ⑤**執行**生成的技能 ⑥驗**最終產出**（封存檔存在且內容正確）。

- 實作：擴充 browser 執行案例格式，讓一個案例涵蓋「規劃→生成→核可→執行→驗」而非只測其中一段。
- 這是目前 400+手寫+exec+browser 都沒有的「一氣呵成」測試,也是矩陣「驗收證據」真正要的東西。

## 5. 標準驗收跑批配方（可重複）

```bash
# 前置：後端指向目標模型 + 種子測試庫；每批重新登入（token 30min）
# L1 全案例：
uv run python -m eval.run --mode api --llm real --no-strict-steps \
  --base-url … --token … --cases eval/cases/generated --tag mX \
  --runs 5 --save-baseline eval/out/<run>/mX/baseline.json --verbose
# L3 生成技能執行：gen_exec_probe（RUNS=5，多技能類型 fixture）
# L4 browser：--mode browser（前端起著，抽樣即可，斷言寬）
# 每個 <run>/ 附 meta.json；與上一版 baseline 用 --baseline 比對回歸
```

## 6. 回歸比較怎麼做

- 每次跑批一個帶日期/配置的目錄 + `meta.json`。
- `--baseline <上次>/baseline.json` 自動比對、退步標紅。
- **比較前先確認 meta 一致**（模型/種子/評分模式/runs）——否則是比不同尺。
